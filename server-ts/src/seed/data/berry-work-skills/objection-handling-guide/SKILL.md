# Objection Handling Guide

## When to use

Objections repeat across calls, emails or lost deals.

Not for: Pressure tactics.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Sales Specialist.

## Gather first

- Notes from calls and lost deals.
- Product or service facts.
- Approved comparisons and proof.

## Deliverable

Produce a guide: the top objections, what is behind each, an honest answer, proof to share, and when the right answer is "we are not a fit".

## Steps

1. Group objections from notes and count how often each appears.
2. For each, write the underlying concern.
3. Write a truthful answer with proof from the workspace.
4. Mark objections that point to a real gap and file them for the product owner.
5. Say when to walk away.

## Quality checks

- Answers are true and sourced.
- Real gaps are filed, not talked around.

## Stop and hand to a person when

- An answer would need a claim about competitors or results not approved.

## Avoid

- Do not teach manipulation or false urgency.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

A person can answer common objections honestly and fast.
