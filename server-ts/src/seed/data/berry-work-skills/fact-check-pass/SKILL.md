# Fact Check Pass

## When to use

A piece will be published, sent to many people or used in a decision.

Not for: Changing facts yourself.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Editor.

## Gather first

- The draft.
- Its source list.

## Deliverable

Produce a fact-check table: claim, location in the draft, source checked, result (confirmed, wrong, unsupported, outdated), and suggested fix for the author.

## Steps

1. List every checkable claim: names, dates, numbers, quotes, titles.
2. Check each against the cited or a primary source.
3. Record the result.
4. Suggest corrections; do not apply them to facts.
5. Flag claims with no source.

## Quality checks

- Every claim in the draft is in the table.
- Sources are opened, not assumed.

## Stop and hand to a person when

- A claim is wrong in a way that could harm someone or breach law.

## Avoid

- Do not confirm a claim from the same source that made it, when a primary source exists.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

The author knows exactly which claims need fixing.
