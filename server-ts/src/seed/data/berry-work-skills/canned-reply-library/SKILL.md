# Saved Reply Library

## When to use

The same answers are typed repeatedly, or replies vary between agents.

Not for: Replacing help articles; replies link to them.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Customer Support Specialist.

## Gather first

- Frequent questions with counts.
- Help articles and policies.
- Voice guidelines.

## Deliverable

Produce a reply library: one entry per frequent question with the reply, placeholders for personal details, the article or policy it relies on, when not to use it, and a review date.

## Steps

1. Rank questions by frequency.
2. Write a short, warm reply for each.
3. Mark placeholders clearly.
4. Link the source for each.
5. Add when not to use a reply (escalation cases).

## Quality checks

- Every reply cites its source.
- Placeholders are obvious.
- No reply promises refunds or dates.

## Stop and hand to a person when

- A reply would state a policy not written down.

## Avoid

- Do not write replies that sound robotic.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

Agents answer common questions fast and consistently.
