# Process Bottleneck Review

## When to use

Work piles up, deadlines slip, or people complain about a process.

Not for: Judging individuals.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Operations Coordinator.

## Gather first

- The current procedure or a walkthrough.
- Timings, volumes and error examples.

## Deliverable

Produce a review: the process mapped step by step with time and wait at each, bottlenecks and error points with evidence, root causes, improvement options with effort and impact, and a recommended first change.

## Steps

1. Map the process as it actually runs.
2. Record time and waiting per step.
3. Find where work waits or errors arise.
4. Identify causes.
5. Propose options and pick a first small change.

## Quality checks

- The map reflects practice, not the ideal.
- Options state effort and impact.

## Stop and hand to a person when

- Fixes need spending, new tools or changes to roles.

## Avoid

- Do not blame people for process problems.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

The team knows the bottleneck and the first fix to try.
