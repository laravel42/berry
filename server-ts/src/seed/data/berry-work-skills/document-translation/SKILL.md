# Document Translation

## When to use

Text exists in one language and readers need it in another.

Not for: Certified or sworn translation.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Translator.

## Gather first

- Source text.
- Target language and country.
- Workspace glossary and intended readers.

## Deliverable

Produce the translation in the original's structure, translator notes on every choice between readings, and new terms proposed for the glossary.

## Steps

1. Read the whole source first for intent and tone.
2. Apply glossary terms.
3. Translate meaning, keeping register.
4. Mark ambiguous passages with the options chosen.
5. Read the translation alone as a native reader would.

## Quality checks

- Nothing is dropped or added without a note.
- Numbers, names and dates are correct.
- Glossary terms are used consistently.

## Stop and hand to a person when

- The text is legal, medical or safety-critical and needs certification.

## Avoid

- Do not soften or strengthen the message.
- Do not present the translation as certified.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

A native reader would not notice it was translated, and every choice is visible.
