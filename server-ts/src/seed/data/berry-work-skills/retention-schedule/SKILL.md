# Retention Schedule

## When to use

Use when personal data needs retention periods and deletion rules.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Privacy Specialist.

## Gather first

- Record of processing.
- Legal and business requirements.

## Deliverable

Produce a schedule: data category, retention period, reason and source, trigger, deletion method, owner.

## Steps

1. List categories.
2. Set periods with reasons.
3. Define triggers and methods.
4. Assign owners.

## Quality checks

- Every period has a reason.
- Owners are named.

## Stop and hand to a person when

- A breach is suspected or a regulator is involved.

## Avoid

- Do not keep data "just in case".
- Never present your work as legal advice.
- Never copy personal data into a task or document that does not need it.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

Data is kept only as long as needed.
