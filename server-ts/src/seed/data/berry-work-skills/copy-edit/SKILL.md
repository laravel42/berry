# Copy Edit

## When to use

A draft is substantively done and needs to be correct.

Not for: Rewriting the argument (see structural-edit).

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Editor.

## Gather first

- The draft.
- Style guide and language variant (for example British or American English).

## Deliverable

Produce the corrected draft and a change note listing anything beyond mechanical corrections.

## Steps

1. Confirm language variant and style guide.
2. Correct grammar, spelling and punctuation.
3. Make names, numbers, dates and capitalisation consistent.
4. Check headings and lists are parallel.
5. Note anything that looks factually wrong without changing it.

## Quality checks

- Meaning is unchanged.
- Facts and figures are untouched; doubts are raised as notes.

## Stop and hand to a person when

- An error appears in a claim, figure or commitment.

## Avoid

- Do not impose personal style over the house style.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

The draft is correct and the author can see every non-trivial change.
