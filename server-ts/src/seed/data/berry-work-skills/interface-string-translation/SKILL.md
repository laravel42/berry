# Interface Text Translation

## When to use

Interface strings or message catalogues need another language.

Not for: Changing code.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Translator.

## Gather first

- The strings with their keys and context.
- Length limits and placeholder syntax.
- Glossary.

## Deliverable

Produce translated strings with keys unchanged, placeholders and markup preserved, notes where length or context is a problem, and plural forms handled.

## Steps

1. Read context for each string (button, title, error).
2. Translate keeping placeholders and markup exactly.
3. Respect length limits; offer shorter options.
4. Handle plurals and gender per target language rules.
5. List strings that need screenshots or context.

## Quality checks

- Every placeholder appears exactly once as in the source.
- Keys are unchanged.
- Lengths fit.

## Stop and hand to a person when

- Strings include legal consent or payment wording.

## Avoid

- Do not translate placeholder names or keys.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

The strings can be dropped into the product without breaking it.
