# Cross-Language Consistency Check

## When to use

A policy, product page or document is maintained in multiple languages and one was updated.

Not for: Retranslating everything.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Translator.

## Gather first

- All language versions with dates.
- The authoritative version.

## Deliverable

Produce a consistency table: section, authoritative text, each language's status (matches, outdated, differs, missing), and the updates needed.

## Steps

1. Confirm which version is authoritative.
2. Compare sections across languages.
3. Mark differences in meaning, not style.
4. List updates per language.
5. Note figures, dates and links that differ.

## Quality checks

- Every section is compared.
- Numbers, dates and links match.

## Stop and hand to a person when

- Language versions differ on legal terms, prices or safety information.

## Avoid

- Do not treat style differences as errors.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

Every language says the same thing, or the gaps are listed.
