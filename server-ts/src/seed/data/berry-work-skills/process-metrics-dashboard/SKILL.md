# Process Metrics Definition

## When to use

Use when a process needs a few measures that show whether it is healthy.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Process Improvement Analyst.

## Gather first

- Process map.
- Goals.

## Deliverable

Produce a measures sheet: lead time, throughput, error rate and any others with definitions, data sources, targets, and owners.

## Steps

1. Pick few measures tied to goals.
2. Define each precisely.
3. Name data sources.
4. Set targets and owners.

## Quality checks

- Definitions are exact.
- Each has an owner.

## Stop and hand to a person when

- A change moves work between teams or changes a role.

## Avoid

- Do not measure what nobody will act on.
- Never propose removing a control or check without saying what it protected.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

The process can be watched and improved.
