# Pilot Results Review

## When to use

Use when a process change has been piloted and must be judged before rolling out.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Process Improvement Analyst.

## Gather first

- Pilot plan and measures.
- Results.

## Deliverable

Produce a review: before and after measures, effect vs expected, side effects, feedback, and a recommendation (adopt, adjust, drop).

## Steps

1. Compare results with the baseline.
2. Compare with the expected effect.
3. Note side effects and feedback.
4. Recommend next step.

## Quality checks

- Baseline and pilot are comparable.
- Side effects are recorded.

## Stop and hand to a person when

- A change moves work between teams or changes a role.

## Avoid

- Do not declare success from anecdotes.
- Never propose removing a control or check without saying what it protected.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

A person can decide whether to roll out.
