# Community Guidelines

## When to use

A community is starting, growing or having trouble with behaviour.

Not for: Moderating in real time; people moderate.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Social Media Manager.

## Gather first

- The community's purpose.
- Examples of problem behaviour.
- Platform rules.

## Deliverable

Produce guidelines: purpose, expected behaviour, what is not allowed with examples, how to report, what moderators do (warn, hide, remove, ban) and an appeal route, plus a moderator playbook.

## Steps

1. State the purpose in a sentence.
2. Write rules in plain language with examples.
3. Define escalating moderator actions.
4. Explain reporting and appeals.
5. Write the moderator playbook for common cases.

## Quality checks

- Rules are consistent with platform terms.
- Actions are proportionate and consistently applied.
- There is an appeal route.

## Stop and hand to a person when

- Reports involve threats, self-harm, child safety or illegal content.

## Avoid

- Do not write rules that can be applied selectively.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

Members know the rules and moderators act consistently.
