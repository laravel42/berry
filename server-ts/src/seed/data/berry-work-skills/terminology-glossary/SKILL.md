# Terminology Glossary

## When to use

Terms are translated inconsistently, or a new language is being added.

Not for: A general dictionary.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Translator.

## Gather first

- Existing documents in both languages.
- Product, service and brand names.

## Deliverable

Produce a glossary table: term, definition, approved translation per language, terms not to translate, forbidden alternatives, and usage notes.

## Steps

1. Extract recurring and specialist terms.
2. Define each in the source language.
3. Choose the approved translation with a reason.
4. Mark names never translated.
5. Record forbidden alternatives.

## Quality checks

- Each term has one approved translation per language.
- Definitions are clear to a newcomer.

## Stop and hand to a person when

- A term has legal or regulated meaning.

## Avoid

- Do not change approved terms without noting it.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

Any translator can use the glossary and stay consistent.
