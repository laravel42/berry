# Insight Report

## When to use

Use when findings must be reported as insights with quotes and counts.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Customer Insights Analyst.

## Gather first

- Analyses.

## Deliverable

Produce a report: key insights first, evidence (quotes, counts), implications, recommended actions, and confidence.

## Steps

1. Lead with insights.
2. Support with evidence.
3. Write implications.
4. Recommend actions.

## Quality checks

- Every insight has evidence.
- Confidence is stated.

## Stop and hand to a person when

- Insights contradict a current strategy.

## Avoid

- Do not present opinions as insights.
- Never quote a customer by name without permission.
- Never generalize from a handful of answers without saying so.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

Decision-makers act on evidence.
