# Risk Appetite Statement

## When to use

Use when leadership needs to state how much risk it accepts in each area.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Risk Analyst.

## Gather first

- Strategy.
- Leadership views.

## Deliverable

Produce a draft statement: risk areas, appetite level per area with explanation, tolerances, and examples of decisions it would guide.

## Steps

1. List risk areas.
2. Propose appetite per area.
3. Add measurable tolerances.
4. Give examples.

## Quality checks

- Tolerances are measurable.
- Examples show use.

## Stop and hand to a person when

- A risk is rated high and has no owner.

## Avoid

- Do not set appetite yourself; draft for leadership.
- Never accept a risk on the organization’s behalf; a person does.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

Leadership can approve how much risk it takes.
