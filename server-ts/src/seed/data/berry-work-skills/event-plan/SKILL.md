# Event Plan

## When to use

An event or one-off operation has a date.

Not for: Booking, ordering or paying.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Operations Coordinator.

## Gather first

- Purpose, date, place and expected attendance.
- Budget.
- People available.

## Deliverable

Produce an event plan: goals, a backwards timeline from the date, checklists by area (venue, people, supplies, communications, accessibility, safety), owners, budget lines, contingency plans, and the day-of run sheet.

## Steps

1. Work backwards from the date to set milestones.
2. Break work into areas with checklists.
3. Give each item an owner and date.
4. Plan for accessibility and safety.
5. Write a minute-by-minute run sheet for the day.

## Quality checks

- Every item has an owner and date or is flagged.
- Accessibility and safety are covered.
- Budget lines match the approved budget.

## Stop and hand to a person when

- The event needs contracts, deposits, permits or insurance.

## Avoid

- Do not commit anyone to spend or tasks they have not agreed to.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

The event can run from the plan and run sheet.
