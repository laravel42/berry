# Training Feedback Revision

## When to use

A course or session has run and feedback or assessment results exist.

Not for: Judging individual learners.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Learning Designer.

## Gather first

- Feedback, anonymised.
- Assessment results by question.
- The materials.

## Deliverable

Produce a revision plan: themes from feedback with counts, questions most learners got wrong and the likely cause, changes proposed per module with priority, and what to keep.

## Steps

1. Group feedback into themes and count them.
2. Find outcomes with weak results.
3. Trace each weak point to material, practice or assessment.
4. Propose specific changes.
5. Note what worked and should stay.

## Quality checks

- Feedback is anonymised.
- Changes are tied to evidence.

## Stop and hand to a person when

- Feedback reports harm, harassment or a safety issue.

## Avoid

- Do not over-react to one comment.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

The next run of the training is measurably better.
