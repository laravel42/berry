# Needs-Based Segmentation

## When to use

Use when customers must be grouped by what they need rather than demographics.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Customer Insights Analyst.

## Gather first

- Research and behaviour data.

## Deliverable

Produce segments: name, needs, behaviours, size estimate, value, and how to identify them.

## Steps

1. Identify distinguishing needs.
2. Group customers.
3. Estimate size.
4. Describe how to identify each.

## Quality checks

- Segments are distinct.
- Sizes cite basis.

## Stop and hand to a person when

- Insights contradict a current strategy.

## Avoid

- Do not segment by protected traits.
- Never quote a customer by name without permission.
- Never generalize from a handful of answers without saying so.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

Teams can target needs.
