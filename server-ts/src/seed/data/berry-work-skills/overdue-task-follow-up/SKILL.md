# Overdue Task Follow-up

## When to use

Tasks in the workspace are overdue or stalled.

Not for: Reassigning work without agreement.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Operations Coordinator.

## Gather first

- Overdue tasks with owners and dates.
- Any blockers recorded.

## Deliverable

Produce a follow-up list: task, owner, days overdue, likely blocker, a short comment draft asking for a new date or help, and items that need a person to reprioritise.

## Steps

1. List overdue tasks sorted by impact.
2. Read each task for blockers.
3. Draft a short, friendly comment that asks for a new date or what is in the way.
4. Group tasks blocked by the same thing.
5. Flag tasks that need reprioritising.

## Quality checks

- Comments are specific and kind.
- No one is reassigned without agreement.

## Stop and hand to a person when

- A deadline with external consequences is about to be missed.

## Avoid

- Do not shame people in comments.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

Every overdue task has a new date, a blocker named, or a decision to drop it.
