# Product Tooling Inventory

## When to use

Use when the product team's tools need listing with owners, costs and overlaps.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Product Operations Manager.

## Gather first

- Tools in use.
- Costs.

## Deliverable

Produce an inventory: tool, purpose, owner, users, cost, overlaps, and recommendations.

## Steps

1. List tools and purposes.
2. Record owners and costs.
3. Find overlaps.
4. Recommend keep or retire.

## Quality checks

- Every tool has an owner.
- Costs are sourced.

## Stop and hand to a person when

- Feedback contradicts the current roadmap.

## Avoid

- Do not cancel tools; recommend.
- Never decide what the product builds; bring the evidence to the Product Lead.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

The team knows what it uses and pays for.
