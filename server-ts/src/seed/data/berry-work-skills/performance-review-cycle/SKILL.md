# Performance Review Cycle

## When to use

A review cycle is starting or the process needs designing.

Not for: Rating or reviewing any individual.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the People Partner.

## Gather first

- Team size, roles and any existing framework.
- Dates and constraints.
- How results are used (development, pay, promotion).

## Deliverable

Produce a review pack: calendar, self-review template, manager template, peer feedback template if used, guidance on evidence-based feedback, and a calibration checklist.

## Steps

1. Set the calendar backwards from the decision date.
2. Write templates that ask for evidence and examples.
3. Give guidance on specific, behaviour-based feedback.
4. Add a calibration step to compare ratings across managers.
5. Explain how results are used, plainly.

## Quality checks

- Templates ask for evidence, not adjectives.
- The process is the same for everyone.
- There is a way to raise disagreement.

## Stop and hand to a person when

- The cycle is tied to pay or dismissal decisions.

## Avoid

- Do not design forced rankings without a person's explicit decision.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

Managers and team members know what to write and when.
