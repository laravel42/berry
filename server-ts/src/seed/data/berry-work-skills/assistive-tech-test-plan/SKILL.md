# Assistive Technology Test Plan

## When to use

Use when a product must be tested with assistive technologies.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Accessibility Specialist.

## Gather first

- Key flows.
- Platforms in scope.

## Deliverable

Produce a test plan: flows, assistive technologies and browsers, tasks, expected behaviour, and a results sheet.

## Steps

1. Pick key flows.
2. Choose technologies per platform.
3. Write tasks and expected behaviour.
4. Prepare a results sheet.

## Quality checks

- Coverage matches users' platforms.
- Expected behaviour is defined.

## Stop and hand to a person when

- A problem blocks a group of users from a core task.

## Avoid

- Do not test only one screen reader if users use several.
- Never declare something compliant without testing it.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

Key flows are proven to work with assistive tech.
