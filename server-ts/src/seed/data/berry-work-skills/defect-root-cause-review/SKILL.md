# Defect Root Cause Review

## When to use

Use when a defect or complaint must be traced to its root cause.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Quality Manager.

## Gather first

- Defect or complaint details.

## Deliverable

Produce a review: problem, containment, root cause with evidence, why it was not caught, corrective and preventive actions.

## Steps

1. Describe the problem and containment.
2. Find the root cause with evidence.
3. Ask why checks missed it.
4. Set corrective actions.

## Quality checks

- Root cause has evidence.
- Actions prevent recurrence.

## Stop and hand to a person when

- A defect could harm someone.

## Avoid

- Do not stop at blaming an individual.
- Never close a corrective action without evidence it worked.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

The defect will not recur.
