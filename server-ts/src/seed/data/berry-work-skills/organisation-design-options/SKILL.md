# Organisation Design Options

## When to use

Use when organisation structure must change.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the Chief People Officer.

## Gather first

- Current structure.
- Goals.

## Deliverable

Produce options: structures, spans, reporting lines, trade-offs, transition risks.

## Steps

1. Describe current structure.
2. Design options.
3. Assess trade-offs.
4. Assess transition risks.

## Quality checks

- Options are realistic.
- Risks are stated.

## Stop and hand to a person when

- A decision affects people’s jobs, pay or wellbeing.

## Avoid

- Do not name individuals in options.
- Never decide anything about one person’s employment.
- Never make a decision that binds the organization; recommend it to a person.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

Leadership can choose a structure.
