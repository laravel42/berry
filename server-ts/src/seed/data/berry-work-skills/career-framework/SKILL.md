# Career Framework

## When to use

Promotions feel arbitrary, or the team is growing.

Not for: Setting pay for levels; a person does.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the People Partner.

## Gather first

- Current roles and titles.
- Examples of strong work at different levels.

## Deliverable

Produce a framework: levels per track, expectations per level across a few dimensions (scope, impact, skills, collaboration), examples, and how progression is assessed.

## Steps

1. Choose a small number of dimensions.
2. Describe each level in observable terms.
3. Add examples from real work, anonymised.
4. Explain how progression is decided.
5. Map current roles to levels for a person to confirm.

## Quality checks

- Levels describe behaviour and impact, not tenure.
- Expectations are observable.

## Stop and hand to a person when

- The framework will be tied to pay bands.

## Avoid

- Do not make years of experience a level requirement.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

People can see what the next level looks like.
