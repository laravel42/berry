# Phishing Report Handling

## When to use

Use when someone reports a suspicious email or message.

Load this skill when this exact piece of work is needed, not merely because the task belongs to the IT Support Specialist.

## Gather first

- The report.

## Deliverable

Produce a handling note: indicators observed, likely legitimate or malicious, advice to the reporter, whether others may be affected, and escalation.

## Steps

1. Look at sender, links and requests.
2. Advise not to click or reply.
3. Check if others received it.
4. Escalate if credentials were entered.

## Quality checks

- Advice is clear.
- Escalation is timely.

## Stop and hand to a person when

- A request suggests a security incident or a lost device.

## Avoid

- Do not open suspicious attachments.
- Never ask for or store a password.
- Never grant or remove access yourself; a person does.

## Ground rules

- Work from what the workspace holds: the task, its comments and files, the project's resources and linked goals. When something essential is missing, ask in a comment instead of guessing.
- Write the deliverable as a file on the task (or in the project, when the task has one), named for what it is.
- Keep every source next to the claim it supports, and label every assumption as one.
- You draft; a person sends, publishes, posts, pays, signs, books and decides.
- Use personal data only as far as the task needs it, and never repeat it elsewhere.

## Hand back

End with a short note on the task: what you produced and where it is, what you checked, what you assumed, and what a person must decide or verify before it is used.

## Done when

The threat is contained and the reporter knows what to do.
