# Subscription-backed AI runtimes across admission and execution

This change adds user-scoped GitHub Copilot execution, connection/catalog APIs, run snapshots, runtime control calls, and frontend selectors. The implementation does not yet bind a subscription selection to the actual compute image, an immutable provider account, or exclusively human-started work. The resulting races and lifecycle gaps can change who is billed, silently execute through Bedrock/Kilo, or leave credential-bearing work running after disconnect.

Watch for: **actual-target native fallback (confirmed)**, **mutable billing-account identity (confirmed)**, **audit attribution becoming subscription consent (confirmed)**, and **disconnect without durable process termination (confirmed)**.

**Verdict**: NEEDS_CHANGES

## High-level view

Capability probing is skipped or sent only to the deployment default, while task execution independently resolves an agent’s actual custom/default host. Because the new runtime field is optional, a stale pre-feature image can discard it and execute Berry’s native Bedrock/Kilo path.

Connections are user/workspace-scoped but mutable across reconnects. Runs and sessions snapshot only the reused row id, while execution opens the latest GitHub token; automatic work also treats inherited `requestedBy` as subscription consent, does not revalidate membership, and re-resolves current preferences on retry.

Disconnect does not serialize against admission or durably stop provider work. HTTP permits plaintext credential transport and shares Copilot control persistence, while AgentCore control invocations remain billable until idle timeout; the frontend triggers those controls during passive rendering.

The Copilot adapter enables an eight-hour infinite session without Berry’s hard turn/output limits. The migration’s delete action contradicts its run snapshot CHECK, and the UI’s human-only/no-fallback claims are not supported by the backend behavior or an immutable per-run billing identity.

<summary>Issues (10)</summary>

1. **Actual-target native fallback (confirmed)** — Runtime compatibility is optional and checked only on the default host, so a stale/custom image can discard the subscription field and execute through Bedrock/Kilo. Preflight the exact resolved target without a user credential and fail closed unless it reports the required adapter protocol/version.
2. **Mutable billing identity (confirmed)** — Reconnect reuses a connection id while changing its account/token lineage, retargeting queued work and warm state. Rotate immutable connection generations, verify and snapshot the account, stop the prior generation, and render that identity on each run.
3. **Audit identity used as subscription consent (confirmed)** — Inherited `requestedBy` authorizes automatic work and remains usable after workspace membership removal. Separate attribution from billing consent, revalidate membership at admission/execution, and revoke/cancel on member removal.
4. **Automatic billing-path change (confirmed)** — Retries and continuations omit the source snapshot and re-resolve current preferences, allowing a Copilot fault to restart on native billing. Copy the original runtime/model/connection generation and fail closed if it is unusable.
5. **Non-atomic disconnect and stop (confirmed)** — Disconnect races new admissions, suppresses cancellation errors, and records cancellation before provider termination is durable. Lock admission/disconnect together and persist a retryable stop operation for every affected target/session.
6. **Plaintext OAuth transport (confirmed)** — Non-loopback `http://` runtime URLs receive the full credential-bearing envelope/control body. Require verified HTTPS outside explicitly local development and reject insecure personal-runtime targets.
7. **Shared Copilot control state (likely)** — HTTP control calls use fixed persistence directories and credential-bearing child environments across users. Use private per-call directories and principal-specific process/container isolation, refusing hosts that cannot attest it.
8. **Unenforced Copilot run budgets (confirmed)** — The adapter enables infinite sessions and an eight-hour wait while ignoring Berry’s hard turn/output/deadline limits. Apply Copilot session limits, enforce counters at the adapter boundary, and emit Berry’s limit/checkpoint outcome.
9. **Billable control-session leak (confirmed)** — AgentCore control invocations are never stopped, and passive frontend rendering invokes live discovery. Stop unique control sessions in `finally` and use cached models with explicit or TTL-based refresh.
10. **Impossible connection deletion invariant (confirmed)** — `ON DELETE SET NULL` conflicts with the CHECK requiring a connection whenever the runtime key is present. Make historical null-connection snapshots legal or retain immutable connection rows, then test deletion and reset paths.

<details><summary>Details</summary>

## Actual compute target can erase the subscription selection

**Confirmed.** `TaskEnvelope.runtime` is nullable and optional (`server-ts/src/runtime/envelope.ts:118-133`). Connection setup treats control as optional (`server-ts/src/mounts/runtimes.ts:251-283`), and the composition root sends available control only to `defaultTarget` (`server-ts/src/index.ts:1046-1054`). Execution resolves the run’s actual host, including custom bindings, and invokes it without a target-specific adapter/version check (`server-ts/src/runtime/task-executor.ts:172-228`).

A runtime image from `main` uses a non-strict top-level Zod object and has no runtime branch, so it strips the new field and enters native execution:

```text
Copilot run -> custom/stale runtime image -> runtime field discarded
            -> native Strands loop -> Bedrock or Kilo billing
```

Probe the exact resolved target before opening or sending the user token, require an adapter protocol/version response for every personal run, and fail closed when absent or incompatible. Refuse to persist a connected runtime without a control seam, and make new envelope versions strict/explicit to prevent future skew.

## A connection id is mutable across billing accounts

**Confirmed.** Reconnect updates the external account and metadata in place (`server-ts/src/runtime/ai-runtimes.ts:162-166`). Runs and provider sessions retain only that row id (`server-ts/src/runtime/envelope-builder.ts:239-262`), while execution reads current labels and opens the user’s latest GitHub token (`server-ts/src/index.ts:633-650`). Relinking account B after account A admitted a run can therefore execute queued work with B and reuse A’s provider-session/filesystem namespace.

Rotate an immutable connection-generation id whenever account or credential lineage changes, snapshot the account/generation on each run, verify live token identity before dispatch, and stop prior-generation work. The UI’s account guarantee (`frontend/components/common/runtimes/runtimes-list.tsx:110-113`) also needs that immutable identity rendered on historical runs; today it only parses runtime/model (`frontend/lib/runs.ts:37-38`).

## `requestedBy` doubles as consent and survives membership revocation

**Confirmed.** Queue admission passes inherited `requestedBy` directly to personal-runtime resolution (`server-ts/src/runs/queue.ts:113-119`), and automatic dependent/review work reuses the original requester (`server-ts/src/agents/review-gate.ts:941-950`). This conflicts with the UI promise that the preference applies only to work the person starts (`frontend/components/common/runtimes/runtimes-list.tsx:305-307`).

Connections reference workspace and user, not membership (`server-ts/migrations/220_subscription_ai_runtimes.up.sql:8-22`), and credential opening checks neither run workspace nor current membership (`server-ts/src/index.ts:633-650`). A removed member’s queued or inherited automation can therefore keep opening that person’s OAuth token. Separate audit attribution from personal-runtime authorization, require direct/bounded consent, revalidate membership at admission and credential open, and make membership removal disconnect, cancel, and stop that principal’s work.

## Automatic follow-on runs can change billing mode

**Confirmed.** Continuations and retryable-fault retries omit the prior run’s runtime/model/connection and call generic admission with only `requested_by` (`server-ts/src/runs/continuation.ts:38-85`, `server-ts/src/runs/continuation.ts:200-235`). Generic admission resolves the issue override and preference at that later moment (`server-ts/src/runs/queue.ts:113-120`). A Copilot run can thus fail retryably after its preference changes and be retried automatically on Bedrock/Kilo.

Copy the originating run’s immutable runtime/model/connection generation for every automatic retry, limit continuation, reviewer rework, and chained run. If that subscription is no longer usable, fail closed; only an explicit manual restart should resolve a fresh selection.

## Disconnect does not close admission or guarantee process stop

**Confirmed.** Disconnect reads the connection and active runs, changes status, and clears preference in separate unlocked statements (`server-ts/src/runtime/ai-runtimes.ts:179-202`); admission checks connected status without locking (`server-ts/src/runtime/ai-runtimes.ts:362-365`). An enqueue can be missed by the active-run read and commit after disconnection.

Cancellation errors are suppressed (`server-ts/src/mounts/runtimes.ts:292-295`), and the callback only marks the ledger row cancelled (`server-ts/src/index.ts:1043-1046`). If the owning worker fails before its next heartbeat/transport stop, the terminal row is no longer swept while the credential-bearing provider process can continue to runtime max lifetime. Lock the connection across admission/disconnect, atomically record cancellation intent for all affected runs, and use a durable stop service that retries against each run’s actual target/session instead of discarding stop failures.

## HTTP runtime transport has no confidentiality requirement for OAuth

**Confirmed.** Runtime configuration accepts arbitrary HTTP or HTTPS URLs (`server-ts/src/config/config.ts:892-895`). The OAuth credential is in the new envelope (`server-ts/src/runtime/envelope.ts:118-129`), and HTTP invocation/control serializes it over that URL (`server-ts/src/runtime/http-transport.ts:41,94`). Bearer authentication does not protect it from network observers.

Allow plaintext only for recognized loopback/local development. Require certificate-verified HTTPS for every non-loopback personal-runtime target and reject insecure connection or execution.

## Copilot control processes share persistence in HTTP mode

**Likely.** Auth and model-discovery clients use fixed process-wide directories while supplying each user’s client-level token (`server-ts/src/agents/runtime/adapters/copilot.ts:102-105,132-135`). The SDK uses `baseDirectory` for session/config persistence and puts a client-level GitHub token in the child environment. AgentCore isolates control session ids into microVMs, but a shared HTTP runtime handles these controls outside per-session identities.

Concurrent users can collide on one persistence/lock namespace, and same-UID work can inspect the credential-bearing child environment. Use a fresh private directory per control, remove it after stop, run it under a principal-specific OS/container identity, and reject subscription controls when a shared HTTP host cannot attest isolation.

## Copilot bypasses Berry’s hard run budgets

**Confirmed.** The provider branch appends only a textual budget contract before invoking the adapter (`server-ts/src/agents/runtime/container/handler.ts:250-323`), unlike the native hard limits (`server-ts/src/agents/runtime/container/handler.ts:433-438`). Copilot enables infinite sessions and waits up to eight hours (`server-ts/src/agents/runtime/adapters/copilot.ts:195-214`) without applying `maxTurns`, `maxOutputTokens`, or a deadline.

Map Berry limits into Copilot `sessionLimits`, independently count root turns/output/usage, abort at the first exceeded ceiling, and return Berry’s limit/checkpoint outcome rather than a generic provider failure.

## Control-only AgentCore sessions are left billable

**Confirmed.** AgentCore `control` invokes and buffers a runtime session, but never calls the separately exposed stop operation (`server-ts/src/runtime/agentcore-transport.ts:121-157`). Connect/model discovery use stable control session ids (`server-ts/src/mounts/runtimes.ts:251-256,327-330`), leaving each control microVM until idle timeout.

The selector performs live discovery on mount (`frontend/components/common/runtimes/runtime-selection.tsx:87-98`) despite already having cached model metadata. Use a unique control session and stop it in `finally`, or reuse a task session only for immediate target preflight. Render cached models and make refresh explicit or TTL-governed rather than a page-view side effect.

## Connection deletion violates its run constraint

**Confirmed.** The run FK uses `ON DELETE SET NULL`, while `runs_ai_runtime_pair_ck` requires every non-null runtime key to retain a connection (`server-ts/migrations/220_subscription_ai_runtimes.up.sql:73-81`). Connection/user cleanup can therefore try to null the FK while preserving the runtime snapshot and fail the CHECK.

Before migration 220 is applied, either retain immutable connection-generation rows with a restrictive FK or allow historical runtime/model snapshots with a null deleted connection while active execution fails closed. Add database tests for user/workspace deletion, connection cleanup, and reset ordering; this review’s DB-backed tests self-skipped because no test database was configured.
